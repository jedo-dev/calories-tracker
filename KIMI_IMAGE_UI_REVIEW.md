# UI/UX regression after image integration

Дата проверки: 2026-06-23  
Проверялось после интеграции изображений, сгенерированных через Opus и подключенных через Kimi.

## Проверено

- [x] Production build frontend: `apps/web`, команда `npm run build` проходит успешно.
- [x] Основные страницы открываются без падения: `/today`, `/entry/new`, `/workouts`, `/products`, `/friends`, `/league`, `/templates`, `/profile`, `/reports`, `/measurements`, `/feed`.
- [x] На desktop и mobile не найден горизонтальный overflow.
- [x] Подключенные `<img>` на проверенных страницах загружаются: `naturalWidth > 0`, битых картинок в DOM не найдено.
- [x] Пустые состояния с картинками работают на `/today`, `/friends`, `/weight`, `/league`, частично на `/workouts`.

## Критичные правки

### 1. Раздут production build из-за общего `assets/images.ts`

**Статус:** баг производительности  
**Файлы:** `apps/web/src/assets/images.ts`, все страницы с импортами из `../assets/images`

Сейчас `images.ts` экспортирует все изображения приложения. Из-за этого production build эмитит почти весь набор ассетов, даже если страница использует только 1-2 картинки. В результате в `dist/assets` попадают десятки изображений по 250-680 KB: навигация, соцкартинки, питание, активности, цели, достижения и т.д.

Что сделать:

- [ ] Убрать массовый barrel-import изображений из `assets/images.ts` для тяжелых `.jpg`.
- [ ] Импортировать картинки напрямую в конкретных страницах, например `import emptyFood from '../assets/03_empty_states/empty_food.jpg'`.
- [ ] Либо разбить на маленькие lazy-модули: `emptyImages.ts`, `workoutImages.ts`, `onboardingImages.ts`, но не импортировать весь каталог сразу.
- [ ] После исправления снова запустить `npm run build` и проверить, что в `dist` не попадают неиспользуемые ассеты.

### 2. В тренировках категория "Руки" получает картинку груди

**Статус:** визуальный баг  
**Файл:** `apps/web/src/pages/WorkoutsPage.tsx`

В UI на `/workouts` категория "Руки" отображает `cat_chest.jpg`, хотя есть отдельный ассет `cat_arms.jpg`.

Причина: в `getCategoryImage` проверка груди идет раньше проверки рук, и обе категории могут иметь emoji `💪`. Поэтому условие груди перехватывает категорию рук.

Что сделать:

- [ ] Для русских названий сначала проверять `рук`, потом fallback по emoji.
- [ ] Не использовать один emoji `💪` как определяющий признак для груди и рук.
- [ ] Для категории "Руки" вернуть `catArms`.
- [ ] Проверить все категории: грудь, спина, ноги, плечи, руки, пресс, кардио.

## Средний приоритет

### 3. Много подготовленных изображений не интегрированы в UI

**Статус:** неполная интеграция  
**Файлы:** `apps/web/src/pages/*.tsx`, `apps/web/src/widget/Footer/Footer.tsx`, `apps/web/src/widget/Drawer.tsx`

Сейчас изображения физически есть и экспортируются, но пользователь почти нигде их не видит.

Не используются или почти не используются:

- `02_nav_icons/*` - навигационные картинки не подключены в нижний nav и меню.
- `05_actions/*` - action-картинки не заменяют действия добавления, удаления, редактирования, меню.
- `06_nutrition/*` - нутриентные картинки не используются на `/today`, в карточках БЖУ и воде.
- `08_mascot/*` - маскот почти не используется в профиле, лиге, успехах, подсказках.
- `11_meal_types/*` - картинки приемов пищи не используются в форме добавления записи и списке записей.
- `12_activity/*` - картинки уровней активности не используются в профиле.
- `13_goals/*` - картинки целей не используются в профиле.
- `14_social/*` - соцкартинки не используются в друзьях/ленте.

Что сделать:

- [ ] Либо удалить/не экспортировать неиспользуемые изображения, чтобы не раздувать проект.
- [ ] Либо точечно интегрировать их там, где они реально усиливают UX.
- [ ] Не заменять системные иконки на большие JPG в кнопках управления. Для кнопок лучше SVG/lucide, картинки использовать как иллюстрации карточек и пустых состояний.

### 4. Пустые состояния интегрированы непоследовательно

**Статус:** UX consistency  
**Файлы:** `ProductsPage.tsx`, `TemplatesPage.tsx`, `MeasurementsPage.tsx`, `ReportsPage.tsx`, `FeedPage.tsx`

На части страниц используются новые empty-state изображения, а на части остались emoji:

- `/products` показывает emoji `🔍` и `😕`, хотя есть `empty_products.jpg`.
- `/templates` показывает emoji `📋`, хотя есть `empty_templates.jpg`.
- `/measurements` показывает emoji `📏`, хотя есть `empty_measurements.jpg`.
- `/reports` показывает только текст, хотя есть `empty_reports.jpg`.
- `/feed` показывает emoji `📰`, отдельного empty-state ассета для feed нет, но есть social/mascot assets.

Что сделать:

- [ ] Подключить соответствующие empty-state изображения на всех страницах.
- [ ] Сделать общий компонент `EmptyState` с props: `image`, `title`, `description`, `action`.
- [ ] Ограничить размер иллюстраций: desktop 120-160px, mobile 96-128px.
- [ ] Для декоративных изображений оставить `alt=""`.

### 5. Профиль почти не использует новые визуальные ассеты

**Статус:** UX opportunity  
**Файл:** `apps/web/src/pages/ProfilePage.tsx`

Профиль все еще выглядит как форма с emoji-аватаром. При этом уже есть изображения для целей и активности:

- `goal_lose_weight.jpg`
- `goal_maintain.jpg`
- `goal_gain_weight.jpg`
- `activity_low.jpg`
- `activity_medium.jpg`
- `activity_high.jpg`
- `activity_very_high.jpg`
- `mascot_fox_main.jpg`

Что сделать:

- [ ] В карточке цели показывать изображение цели: похудение/поддержание/набор.
- [ ] Для выбора активности добавить компактные visual options вместо обычного select или хотя бы preview-картинку выбранной активности.
- [ ] В верхней карточке профиля использовать маскота/аватар как изображение, а emoji оставить fallback.
- [ ] Не перегружать профиль большими картинками: одна hero-карточка + маленькие visual chips достаточно.

### 6. Нижняя навигация не использует новые nav assets

**Статус:** несоответствие ожиданию от интеграции  
**Файл:** `apps/web/src/widget/Footer/Footer.tsx`

В assets есть набор `nav_*`, но Footer продолжает использовать старые SVG-иконки: `StarIcon`, `BellIcon`, `ProfileIcon`, `SettingsIcon`.

Что сделать:

- [ ] Решить продуктово: оставить SVG для навигации или перейти на новые nav-картинки.
- [ ] Если оставляем SVG, убрать `nav_*` из общего экспорта и не тянуть их в build.
- [ ] Если используем картинки, сделать единый компонент `NavIconImage` с фиксированным размером 24-28px, `object-fit: cover/contain`, `border-radius`, активным состоянием и fallback.

## Низкий приоритет / полировка

### 7. Размеры картинок сейчас жестко зашиты inline-стилями

**Файлы:** `FoodList`, `FriendsPage`, `WorkoutsPage`, `WeightHistoryPage`, `LeaguePage`

Много повторов вида:

- `width: 120px`
- `height: 120px`
- `objectFit: contain`
- `opacity: 0.8`

Что сделать:

- [ ] Вынести повторяющиеся стили в компонент `Illustration`.
- [ ] Настроить варианты: `empty`, `category`, `badge`, `profile`.
- [ ] Для категорий использовать одинаковый контейнер и не позволять изображению менять высоту карточки.

### 8. Часть изображений слишком тяжелые для маленького отображения

**Статус:** performance/asset optimization

Многие картинки 1024-1200px и весят 300-680 KB, но отображаются как 24px, 80px или 120px.

Что сделать:

- [ ] Сжать JPG в WebP/AVIF.
- [ ] Сделать отдельные размеры для UI: 128px/256px для маленьких иллюстраций.
- [ ] Для бейджей лиги не использовать 1024px source при отображении 24px.
- [ ] Добавить lazy loading для декоративных изображений ниже первого экрана: `loading="lazy"`.

### 9. Проверить исходники на случайные mojibake-строки

**Статус:** maintainability risk

В некоторых файлах видимые строки и emoji в исходниках выглядят как перекодированные символы при чтении из терминала. В браузере часть текста отображается нормально через i18n, но для будущих правок это риск.

Что сделать:

- [ ] Все пользовательские строки вынести в `i18n/ru.ts`.
- [ ] Убрать inline-строки на русском из страниц, где возможно.
- [ ] Проверить encoding файлов как UTF-8.
- [ ] Не хранить emoji/русский текст в поврежденном виде.

## Рекомендованный порядок исправлений

1. Починить performance-баг с `assets/images.ts`, чтобы build не тянул все картинки.
2. Исправить маппинг категории "Руки" -> `catArms`.
3. Ввести общий компонент `EmptyState` и подключить недостающие empty-state изображения.
4. Доработать профиль с goal/activity/mascot ассетами.
5. Принять решение по nav/action assets: использовать осознанно или убрать из экспорта.
6. Оптимизировать размер изображений и добавить lazy loading.

## Контроль после исправлений

- [ ] `npm run build` проходит.
- [ ] В `dist/assets` нет изображений, которые не используются текущими маршрутами.
- [ ] `/workouts`: "Руки" показывает `cat_arms.jpg`, "Грудь" показывает `cat_chest.jpg`.
- [ ] `/products`, `/templates`, `/measurements`, `/reports`: пустые состояния с иллюстрациями.
- [ ] `/profile`: видны релевантные изображения цели/активности или маскота.

- [ ] Decorative images имеют `alt=""`, meaningful images имеют понятный `alt`.
