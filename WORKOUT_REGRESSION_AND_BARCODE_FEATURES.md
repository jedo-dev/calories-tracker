## Найденные Проблемы

### P1

- [ ] **Активная тренировка стартует пустой.**
  - Симптом: пользователь выбирает категорию, нажимает "Начать тренировку", попадает в `/workout/:sessionId`, но видит "Упражнения не добавлены".
  - Это ломает ожидание: если пользователь стартует тренировку из категории "Грудь", он ожидает хотя бы предложенный список упражнений или выбор упражнений перед стартом.
  - Ожидаемо:
    - либо перед стартом показать выбор упражнений;
    - либо создать тренировку с дефолтным набором упражнений;
    - либо переименовать действие в "Создать пустую тренировку".

- [ ] **Добавление упражнения в активной тренировке семантически слабое.**
  - После клика "+ Добавить упражнение" появляется список упражнений.
  - В accessibility snapshot упражнения выглядят как текстовые элементы, а не как явные кнопки.
  - Ожидаемо:
    - каждое упражнение должно быть `button`;
    - у него должен быть понятный текст;
    - должна быть видимая реакция выбора.

### P2

- [ ] **Прогноз веса не защищен от аномалий.**
  - Симптом: в профиле прогноз показывает `Тренд за неделю -171.5 кг/нед`.
  - Вероятная причина: история веса содержит выбросы вроде `91 -> 95 -> 42`.
  - Ожидаемо:
    - не использовать подозрительные точки в прогнозе;
    - показывать предупреждение "Похоже, вес введен ошибочно";
    - дать пользователю исправить или подтвердить значение.

- [ ] **Слипшийся текст в UI.**
  - `/products`: `Ряженка 1%К: 40...`
  - `/workouts`: `Грудь1 упражнений · 1мин 40сек`
  - Ожидаемо: добавить отступы, переносы или отдельные строки для label/value.

## Улучшения Для Workout-Flow

### 1. Тренировочные Шаблоны

Цель:
- Пользователь нажимает "Начать тренировку" и сразу получает готовую тренировку, а не пустую сессию.

MVP:
- Для каждой категории хранить дефолтный набор упражнений.
- При старте категории автоматически добавлять 4-6 упражнений.
- У каждого упражнения дефолт:
  - подходы;
  - повторы;
  - отдых;
  - примерный расход калорий.

Пример:
- Грудь:
  - Жим штанги лежа `4x10`
  - Жим гантелей лежа `3x12`
  - Разведение гантелей `3x12`
  - Отжимания `3x15`

### 2. Конструктор Перед Стартом

Цель:
- Дать пользователю контроль до создания сессии.

UX:
- На `/workout/category/:categoryId` рядом с каждым упражнением добавить чекбокс.
- Кнопка: "Начать с выбранными".
- По умолчанию выбраны рекомендуемые упражнения.

MVP:
- Local state выбранных exercise ids.
- POST `/workouts/sessions` создает сессию.
- Затем пачкой POST `/workouts/sessions/:id/exercises`.

### 3. Прогресс По Упражнениям

Цель:
- Сделать тренировки мотивирующими и измеримыми.

Фичи:
- Показывать прошлый результат по упражнению.
- Подсказка:
  - "В прошлый раз: 40 кг x 10"
  - "Попробуй 42.5 кг"
- График по упражнению:
  - рабочий вес;
  - повторения;
  - объем.

### 4. Умные Рекомендации По Тренировкам

Примеры:
- "Грудь уже была 2 дня назад, можно повторить."
- "Ты давно не тренировал ноги."
- "После силовой сегодня стоит добрать белок."
- "Сегодня лучше легкая кардио-сессия."

### 5. План Недели

Цель:
- Объединить питание и тренировки.

Пример:
- Пн: грудь + повышенная норма белка.
- Ср: спина.
- Пт: ноги.
- Вс: замеры и вес.

MVP:
- Простая недельная сетка.
- Отмечать выполненные тренировки.
- Подсвечивать пропущенные.

## Заготовка Под Скан Штрихкода

Сейчас явной заготовки под скан штрихкода в UI не видно. Ниже план, который можно отдать на реализацию.

### Цель

Пользователь должен быстро добавить продукт по штрихкоду, не вводя название и КБЖУ вручную.

### Где Разместить

1. `/entry/new`
   - Рядом с полем "Продукт" добавить кнопку с иконкой сканера.
   - Текст/label: "Сканировать штрихкод".

2. `/products`
   - Вверху рядом с поиском добавить action:
     - "Скан"
     - или icon button с `aria-label="Сканировать штрихкод"`.

3. Empty state продукта
   - Если продукт не найден:
     - "Сканировать штрихкод"
     - "Создать продукт вручную"

### UX-Сценарии

#### Сценарий 1: Продукт Найден

1. Пользователь нажимает "Сканировать штрихкод".
2. Открывается камера или поле ручного ввода.
3. Штрихкод распознан.
4. Приложение ищет продукт по barcode.
5. Показывает карточку:
   - название;
   - бренд;
   - КБЖУ на 100 г;
   - источник данных;
   - кнопка "Добавить".
6. Пользователь вводит граммы.
7. Запись добавляется в дневник.

#### Сценарий 2: Продукт Не Найден

1. Штрихкод распознан.
2. API не нашел продукт.
3. Показывается экран:
   - "Продукт не найден"
   - barcode уже заполнен;
   - форма создания продукта.
4. Пользователь вводит:
   - название;
   - бренд;
   - kcal;
   - protein;
   - fat;
   - carbs.
5. Продукт сохраняется в базу и сразу добавляется в дневник.

#### Сценарий 3: Камера Недоступна

1. Пользователь нажимает "Сканировать".
2. Камера недоступна или permission denied.
3. Показывается fallback:
   - поле "Введите штрихкод вручную";
   - кнопка "Найти".

### API-Модель

Добавить поля в product schema:

```ts
barcode?: string;
brand?: string;
source?: 'SYSTEM' | 'USER' | 'OPEN_FOOD_FACTS' | 'BARCODE';
verified?: boolean;
createdBy?: ObjectId;
```

Индексы:

```ts
barcode: unique sparse index
nameNormalized: index
```

### API Endpoints

#### GET `/products/barcode/:barcode`

Назначение:
- Найти продукт по barcode.

Ответ если найден:

```json
{
  "_id": "...",
  "name": "Йогурт натуральный",
  "brand": "Brand",
  "barcode": "460...",
  "kcalPer100g": 60,
  "proteinPer100g": 4.3,
  "fatPer100g": 1.5,
  "carbPer100g": 6.2,
  "source": "USER",
  "verified": false
}
```

Ответ если не найден:

```json
{
  "found": false,
  "barcode": "460..."
}
```

#### POST `/products`

Расширить текущий create product:
- принимать `barcode`;
- принимать `brand`;
- сохранять `source: 'USER'`.

#### POST `/entries`

Без изменений:
- после нахождения продукта пользователь добавляет entry как обычно.

### Frontend Components

Props:

```ts
interface BarcodeScannerButtonProps {
  onDetected: (barcode: string) => void;
}
```

Поведение:
- открывает scanner sheet/modal;
- если камера доступна, запускает сканирование;
- если нет, показывает ручной ввод.

- `error`

#### `ProductCreateFromBarcodeForm`

Поля:
- barcode readonly;

- brand;
- kcal;
- protein;
- fat;
- carbs.

### Библиотека Для Сканирования

Варианты:

1. `@zxing/browser`
   - Хороший вариант для web.
   - Поддерживает barcode scanning через камеру.

2. `html5-qrcode`
   - Популярная библиотека.
   - Быстро подключается.

Рекомендация:
- Начать с `@zxing/browser`.

### Telegram WebApp Ограничения

Проверить:
- доступна ли камера внутри Telegram WebView;
- как работает permission prompt;
- поведение на iOS и Android.

Fallback обязателен:
- ручной ввод штрихкода.

### MVP Порядок Реализации

1. Добавить `barcode` и `brand` в product schema.
2. Добавить endpoint `GET /products/barcode/:barcode`.
3. Добавить ручной ввод штрихкода в `/entry/new`.
4. Если продукт найден - заполнять выбранный продукт.
5. Если не найден - показывать форму создания продукта.
6. Потом добавить камеру через `@zxing/browser`.
