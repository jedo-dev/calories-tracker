# Regression review: Calorie Tracker

Дата проверки: 2026-06-24  
Окружение: Windows, локально `http://127.0.0.1:5173`, API `http://localhost:3000`  
Аккаунт: `megamanok99@gmail.com` / `testtest`

- Запуск API и web.
- Логин email/password.
- Today: быстрые записи, вода, вес, добавление еды.
- Навигация: Лига, Лента, Друзья, Профиль, меню.

## Итог по запуску и сборкам

- `apps/web`: `npm run build` проходит.
- `apps/api`: после `npm install` сборка `npm run build` проходит.
- API стартует на `3000`, `/health` возвращает `{"ok":true}`.
- Web стартует на `5173`.
- В `apps/web/.env` сейчас зашит `VITE_API_URL=https://b1g11r20-5173.euw.devtunnels.ms/api`. Из-за этого локальный логин ломается CORS-ошибкой. Для продолжения регресса web был запущен с override `VITE_API_URL=http://localhost:3000`.

## Блокеры и критичные баги

### 1. Локальный логин не работает с текущим `apps/web/.env`

Фактически frontend на `http://127.0.0.1:5173` отправляет `POST /auth/login` на `https://b1g11r20-5173.euw.devtunnels.ms/api/auth/login`.

Результат:

- В UI: `Ошибка входа`.
- В console: CORS/preflight error.
- В network: `POST https://b1g11r20-5173.euw.devtunnels.ms/api/auth/login => net::ERR_FAILED`.

Ожидаемо: локальная разработка должна ходить на локальный API или на `/api` proxy без ручного override.

### 2. В редакторе блюда нижняя навигация перекрывает кнопку сохранения

Страница: `/recipes/new`.

При попытке нажать `Сохранить блюдо` Playwright получил ошибку:

`<button aria-label="Открыть меню">` из нижней навигации перехватывает pointer events.

Ожидаемо: кнопка сохранения должна быть кликабельна на мобильном/узком viewport. Нужно добавить достаточный `padding-bottom`, изменить layout или закрепление footer.

### 3. Замеры тела фактически не дают ввести новые значения

Страница: `/measurements`.

Видно:

- заголовок `Замеры тела`;
- кнопка `Сохранить замеры`;
- история замеров.

Но полей ввода нет, пока не нажать кнопку. При этом текст кнопки звучит как действие сохранения, а не как открытие формы. Это ломает сценарий: пользователь не понимает, как добавить замер.

Дополнительно история отображается склеенно: `Талия60`, `Бёдра90`, `Грудь90`, без пробелов и единиц измерения.

## Высокий приоритет

### 4. Записанный вес не отражается в профиле

Сценарий:

1. На Today нажать `Записать вес`.
2. Ввести `70.5`.
3. Сохранить.
4. Перейти в `/profile`.

Фактически профиль показывает:

- `Текущий вес: 91 кг`;
- поле `Вес (кг): 91`.

Ожидаемо: после логирования веса пользователь должен видеть актуальный вес или явное разделение между "вес профиля" и "история веса".

### 5. Внешние картинки упражнений падают без надежного fallback

Страница активной тренировки.

Console errors:

- `https://static.wger.de/media/exercise-images/192/Barbell-bench-press-1.png => net::ERR_NAME_NOT_RESOLVED`
- `https://static.wger.de/media/exercise-images/195/Dumbbell-flyes-1.png => net::ERR_NAME_NOT_RESOLVED`
- `https://static.wger.de/media/exercise-images/182/Push-ups-1.png => net::ERR_NAME_NOT_RESOLVED`
- `https://static.wger.de/media/exercise-images/193/Dumbbell-bench-press-1.png => net::ERR_NAME_NOT_RESOLVED`

Картинки завязаны на внешний домен. Если домен недоступен, UI теряет изображения. Лучше хранить локальные ассеты или показывать стабильный placeholder.

### 6. `npm audit` в API: 31 vulnerability, 11 high

Команда: `npm audit --audit-level=high` в `apps/api`.

Итог:

- 31 vulnerability total;
- 11 high;
- среди важных пакетов: `mongoose`, `multer`, `lodash`, `glob`, `minimatch`, `path-to-regexp`, `webpack`, `tmp`.

Часть исправлений требует breaking updates (`@nestjs/*` до v11), поэтому это лучше чинить отдельной задачей с регрессом API.

### 7. Backend warning: дублирующий индекс `barcode`

При старте API:

`[MONGOOSE] Warning: Duplicate schema index on {"barcode":1} found`

Нужно убрать дублирование между `index: true` и `schema.index()` в схеме продукта.

## Средний приоритет

### 8. В редакторе блюда не хватает перевода

Страница: `/recipes/new`.

Фактически кнопка режима расчета отображается как сырой ключ:

`recipeEditor.ingredients`

Console warnings:

`Translation key not found: recipeEditor.ingredients`

Ожидаемо: русский текст вроде `Из ингредиентов`.

### 9. Возможны неконсистентные КБЖУ у блюд

Страница: `/recipes`.

Пример из текущих данных:

`Ff`: `18 ккал · Б55.0 Ж55.0 У52.0 на 100 г`.

Это физически невозможно: одни только белки/жиры/углеводы дают намного больше калорий. Нужно добавить бизнес-валидацию или хотя бы warning при ручном вводе КБЖУ.

### 10. В отчетах сожженные калории отображаются как отрицательные

Страница: `/reports`.

В карточках:

- summary: `Сожжено всего 234`;
- день: `−234 ккал`.

Для расхода калорий минус может быть математически понятен, но в UI рядом с "сожжено" выглядит как отрицательное значение. Лучше унифицировать формат: `234 ккал сожжено` или отдельная иконка расхода без минуса.

### 11. Текст в активной тренировке склеивается

Страница активной тренировки.

Примеры:

- `155Сожжено ккал`;
- `4Упражнений`;
- `16мин 51секДлительность`.

Нужно поправить layout/отступы между числом и подписью.

### 12. В Лиге склеены подписи и значения

Страница: `/league`.

Примеры:

- `XP за неделю86`;
- `Всего XP86`.

Нужно добавить пробел/разделитель или разнести значение и label визуально.

### 13. Тип приема пищи "Другое" в списке записей отображается как `—`

Сценарий:

1. Добавить запись через `/entry/new`.
2. Оставить тип приема пищи `Другое`.
3. Вернуться на Today.

Фактически в списке записей сверху стоит `—`. Ожидаемо: `Другое` или понятная метка, иначе выглядит как потерянное значение.

### 14. Quick add показывает дублирующиеся порции

На Today в "Быстром добавлении" у `Кофе с молоком` были две одинаковые кнопки `100г`.

Ожидаемо: не показывать дубль, если последняя порция совпадает с дефолтной.

### 15. Quick add предлагает странную порцию `1г`

После тестового добавления `Рыба жареная` на `1г` быстрые действия начали предлагать `1г`. Для быстрого сценария это почти бесполезная порция и может быть случайной ошибкой пользователя.

Можно фильтровать слишком маленькие значения или показывать их только в истории, но не как quick preset.

## Низкий приоритет / UX / доступность

### 16. Интерактивные карточки часто сверстаны как `div`, а не `button/link`

Замечено в:

- результатах поиска продуктов;
- результатах поиска в добавлении записи;
- карточках категорий тренировок;
- карточках упражнений.

Для мыши работает, но хуже для клавиатуры, screen reader и автотестов. Лучше использовать `button`, `a` или ARIA role + keyboard handlers.

### 17. Ошибки форм часто показываются через системный `alert`

Пример: пустое сохранение записи показывает alert `Пожалуйста, выберите продукт`.

Работает, но для Telegram WebApp и мобильного UX лучше inline validation рядом с полем.

### 18. Drawer оставляет много фоновой навигации в accessibility tree

При открытом меню в snapshot видны и элементы drawer, и нижняя навигация/контент под ним. Стоит проверить `aria-hidden`, focus trap и управление фокусом.

### 19. React Router future warnings

В console постоянно:

- `v7_startTransition`;
- `v7_relativeSplatPath`.

Не ломает приложение сейчас, но лучше включить future flags или запланировать миграцию, чтобы обновление React Router не стало внезапным регрессом.

### 20. README и часть исходников выглядят как битая кодировка

В `README.md` и некоторых JSX-строках виден mojibake (`Рџ...`, `СЏ...`). В UI часть строк отображается нормально через i18n, но hardcoded alert/aria/label могут всплывать сломанными строками в редких состояниях.
