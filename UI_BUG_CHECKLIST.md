# UI Bug & UX Checklist

Контекст проверки:
- Дата проверки: 2026-06-23.
- Локальный web: `http://127.0.0.1:5173`.
- API: `http://localhost:3000`.
- Авторизация: `megamanok99@gmail.com / testtest`.
- Основной viewport проверки: mobile `390x844`, как Telegram WebApp.

## P0 / P1: сломанная верстка и логика

- [ ] **Починить горизонтальный overflow на странице веса `/weight`.**
  - Симптом: страница шире экрана (`documentWidth` около `447px` при viewport `390px`), верхние карточки статистики уезжают вправо, часть третьей карточки обрезается.
  - Симптом: форма "Записать вес" с датой, полем кг и кнопкой в одну строку не помещается; поле веса сжимается почти до нуля.
  - Где смотреть: `apps/web/src/pages/WeightHistoryPage.tsx`, блок статистики с `gridTemplateColumns: '1fr 1fr 1fr'`, форма на `display: 'flex'`.
  - Ожидаемо: на мобильном карточки должны переноситься или становиться 1-2 колонками; форма должна быть читаемой, без горизонтального скролла.

- [ ] **Починить горизонтальный overflow на странице тренировок `/workouts`.**
  - Симптом: двухколоночная сетка категорий не помещается, правые карточки обрезаются.
  - Где смотреть: `apps/web/src/pages/WorkoutsPage.tsx`, `gridTemplateColumns: 'repeat(2, 1fr)'`.
  - Ожидаемо: адаптивная сетка через `minmax`, `auto-fit`, либо одна колонка на узких экранах.

- [ ] **Починить табы на странице друзей `/friends`.**
  - Симптом: третий таб "Подписчики" обрезается справа.
  - Где смотреть: `apps/web/src/pages/FriendsPage.tsx`, контейнер табов с тремя кнопками `flex: 1`.
  - Ожидаемо: табы помещаются на 390px, переносятся, скроллятся горизонтально осознанно, либо используют компактный segmented control.

- [ ] **Починить поиск продуктов `/products`: сейчас search фактически игнорируется API.**
  - Симптом: при запросе `ряженка` список начинается с "Молоко", "Кефир", а точные совпадения ниже.
  - Причина: в `apps/api/src/products/products.service.ts` создается `queryFilter`, но запрос выполняется как `.find({})`.
  - Ожидаемо: `.find(queryFilter)`, сортировка точных/начинающихся совпадений выше, лимит применяется после фильтрации.

- [ ] **Добавить нормальное начальное состояние на `/products`.**
  - Симптом: до ввода поискового запроса экран выглядит пустым: только поле поиска и footer.
  - Ожидаемо: подсказка вроде "Начните вводить название продукта", популярные продукты, недавние продукты или skeleton/empty state.

## P2: читаемость, интерактивность, UX

- [ ] **Исправить контраст select-полей на `/profile`.**
  - Симптом: значения "Мужской", "Средняя", "Похудение" почти не читаются: светлый фон и белый текст.
  - Ожидаемо: текст select должен иметь достаточный контраст в текущей теме, включая раскрытое состояние.

- [ ] **Улучшить нижнюю навигацию.**
  - Симптом: элементы footer сделаны `div onClick`, а не `button`/`nav`/`a`.
  - Симптом: центральная кнопка меню в DOM пустая, нет доступного имени.
  - Где смотреть: `apps/web/src/widget/Footer/Footer.tsx`, `apps/web/src/widget/BurgerMenu.tsx`.
  - Ожидаемо: использовать `button` или `NavLink`, добавить `aria-label`, активное состояние, keyboard focus.

- [ ] **Добавить `aria-label` для иконок-кнопок на `/today`.**
  - Симптом: кнопки редактирования/удаления записи отображаются как пустые button в DOM.
  - Симптом: кнопка с иконкой шаблонов `📋` имеет неочевидное действие.
  - Ожидаемо: `aria-label="Редактировать запись"`, `aria-label="Удалить запись"`, `aria-label="Открыть шаблоны"` и т.п.

- [ ] **Добавить понятные подписи для стрелок даты.**
  - Симптом: кнопки `←` и `→` на `/today` и `/reports` не объясняют действие.
  - Ожидаемо: `aria-label="Предыдущий день"`, `aria-label="Следующий день"`, для отчетов - предыдущая/следующая неделя или месяц.

- [ ] **Сделать feedback при невалидном email на логине.**
  - Симптом: если ввести `testtest / testtest`, browser native validation блокирует submit из-за `type="email"`, но пользователь не видит кастомного сообщения приложения.
  - Ожидаемо: явное сообщение "Введите email в формате name@example.com" или встроенная валидация с подсветкой поля.

- [ ] **Локализовать серверные ошибки авторизации.**
  - Симптом: при неверных данных показывается `Invalid credentials`.
  - Ожидаемо: русское сообщение, например "Неверный email или пароль".

- [ ] **Добавить заголовки/контекст на пустые или короткие экраны.**
  - Симптом: `/feed` показывает только "Нет событий" без заголовка.
  - Симптом: `/products` до поиска не объясняет, что делать.
  - Ожидаемо: короткий заголовок экрана и полезный empty state.

- [ ] **Проверить нижний padding контента под fixed footer.**
  - Симптом: на `/today` записи и нижние действия визуально прижаты к footer; на длинных списках footer может перекрывать последний элемент.
  - Ожидаемо: общий layout должен добавлять безопасный нижний отступ с учетом footer и Telegram safe area.

- [ ] **Улучшить карточки тренировок на мобильном.**
  - Симптом: текст описаний на карточках визуально слипается с названием (`ГрудьВерхняя часть...`, `СпинаШирочайшие...`).
  - Ожидаемо: нормальные отступы, переносы, ограничение высоты/строк, более компактная типографика.

- [ ] **Улучшить визуал графика веса.**
  - Симптом: график на `/weight` выглядит как несколько больших прямоугольников без понятной шкалы; при небольшом количестве точек занимает много места.
  - Ожидаемо: понятная подпись осей/точек, корректная ширина, отсутствие выезда за viewport.

- [ ] **Добавить подтверждение на destructive actions.**
  - Симптом: кнопки удаления записей/шаблонов выглядят как маленький `X` или пустая иконка; неясно, есть ли подтверждение.
  - Ожидаемо: confirmation sheet/dialog перед удалением и понятная подпись действия.

## P2 / P3: accessibility и семантика

- [ ] **Сделать onboarding indicators недекоративными или скрыть от accessibility tree.**
  - Симптом: точки/индикаторы слайдов определяются как кнопки без названия.
  - Ожидаемо: если кликабельны - `aria-label="Слайд 1"`; если декоративны - не button и `aria-hidden`.

- [ ] **Исправить footer как навигационный landmark.**
  - Ожидаемо: `nav` с понятными ссылками/кнопками, keyboard navigation, focus styles.

- [ ] **Проверить размеры touch targets.**
  - Симптом: некоторые иконки-кнопки редактирования/удаления около `26x29px`, меньше рекомендуемых мобильных touch targets.
  - Ожидаемо: минимум около `44x44px` для основных touch actions.

- [ ] **Проверить focus states.**
  - Симптом: у кастомных clickable `div` нет нормального focus state.
  - Ожидаемо: видимый focus для keyboard users.

## UX-улучшения сверх багов

- [ ] **Сделать продукты реально полезными как справочник.**
  - Показать популярные/недавние продукты до поиска.
  - Добавить состояние "ничего не найдено" с предложением создать продукт.
  - Подсвечивать совпавшую часть названия.
  - Сортировать результаты по релевантности: exact > startsWith > contains.

- [ ] **Унифицировать заголовки экранов.**

  - Лучше вынести общий компонент segmented control с overflow/wrap правилами.

- [ ] **Улучшить микро-копирайт empty states.**
  - `Нет данных` и `Нет событий` лучше заменить на более конкретные сообщения: что это значит и что можно сделать дальше.

- [ ] **Проверить все экраны на 360px ширине.**
  - 390px уже выявил overflow; на 360px проблемы будут заметнее.
  - Минимум проверить: `/today`, `/friends`, `/workouts`, `/weight`, `/entry/new`, `/profile`.

- [ ] **Добавить smoke UI-тесты или Playwright visual checks.**
  - Проверять отсутствие horizontal scroll: `document.documentElement.scrollWidth <= window.innerWidth`.
  - Проверять основные маршруты после логина.
  - Проверять, что search products реально фильтрует результат.
